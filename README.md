# BigMacMcpCN · 智能订单撮合 MCP + Skill

v4：一段复杂口述得到 1–2 个核价组合与理由；后续口述连续修正，选择并授权后创建自取订单。结合账号、地点、目标时间、天气／距离、真实菜单与门店券；本机记住明确偏好、同行者与反馈，区分选择、满意与付款。不绑定模型 API。

接入与能力边界：[MATCHING.md](MATCHING.md) · [可移植 Skill](skills/mcd-order-match/SKILL.md) · [MCP 配置](mcp-config.example.json)。模型负责语义与证据审查，工具负责结构校验和有界撮合；不承诺全菜单最低价或最快出餐。小程序登录不等于 MCP 授权。

任务拆解与验收：[V4_DELIVERY.md](V4_DELIVERY.md)。13 个 MCP 工具覆盖会话、记忆、A/B、创建和状态；未满足硬条件可给条件方案，但禁止创建。付款由用户完成。

文末保留 v2 最少改餐决策器及历史能力说明。新产品入口使用 `run_matching_server.py`；旧增强服务器尚未逐工具验证，不作为 v4 撮合证据。

## 真实使用场景

主产品面向个人点餐和小范围聚餐：先给组合，用户补一句即可调整。当前为即时／未来 24 小时**到店自取**，不是企业批量配送系统。

| 场景 | 用户可以这样说 | 当前能力与边界 |
|---|---|---|
| 一个人省钱选餐 | “我在上海七宝，想吃双层吉士和可乐，给我两个省钱组合。” | 查真实菜单、可用券候选、整单核价；不承诺全菜单最低价 |
| 多人意见不一致 | “四个人，一人要鸡腿，一人只想小食，另外两人随便，下午三点取。” | 宿主仲裁人物／默认理解，动态组合套餐与单点，说明每人分配 |
| 临时改口／人员变更 | “Tom改吃鸡翅，小明不来了，其他人的要求保留。” | 保留对话状态、提交完整新需求、旧报价失效，重新组合核价 |
| 时间与出行取舍 | “别太远，最多走十分钟，贵一点也可以。” | 目标营业时间、关键词距离与步行估算；坐标授权后可结合天气，不保证出餐时间 |
| 模糊口语偏好 | “我减肥，汉堡不要调料；Maggie不吃青菜。” | 先按语境解释不加酱／不要生菜，披露其他含义；去酱／去菜未验证时给条件方案，不能创建 |
| 经常和固定同伴吃饭 | “记住我平时喜欢鸡腿；今天跟上次那两个人一起吃。” | 本机明确偏好与会话／反馈记忆；本次和长期分开，当前要求优先 |
| 选中后下单 | “选A，按刚才展示的金额下单。” | 选中、授权、重核价、金额上限、创建防重；返回支付链接，用户自行付款。创建仍只有模拟接口验收，未真实下单 |

## 如何开始使用新版

### 方式一：在支持 MCP 的大模型客户端里直接说需求（主要入口）

1. 准备 Python 3.11+、支持 MCP stdio 的客户端，以及本人麦当劳 MCP Token。[官方入口](https://open.mcd.cn/mcp) 先手机号验证再申请授权。Token 通过客户端环境变量／凭据管理提供，不提交到 Git。
2. 获取 `miao` 分支并安装依赖；已有本项目 Mac 启动器也可完成依赖安装。

```bash
git clone --branch miao https://github.com/godlockin/BigMacMcpCN.git
cd BigMacMcpCN
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

3. 参照 [mcp-config.example.json](mcp-config.example.json)，先配置其中的 **mcd-order-matcher**。command 使用本机 `.venv/bin/python` 绝对路径，args 使用 `run_matching_server.py` 绝对路径，环境变量提供 `MCD_MCP_TOKEN`。Windows 使用 `.venv/Scripts/python.exe`。`${PROJECT_ROOT}`、`${MCD_MCP_TOKEN}` 是否替换由客户端决定，不能假设所有客户端都支持。
4. 加载 [mcd-order-match Skill](skills/mcd-order-match/SKILL.md)。客户端不支持 Skill 时，将正文作为项目／助手指令。MCP 负责业务工具，Skill 指导模型理解原话、调用顺序与语义仲裁；只配置 MCP 不代表模型自动知道全部流程。无需另接模型 API，语音转写由客户端提供。
5. 在该客户端直接输入下面例子。它应返回最多两组套餐／单点组合、分配、价格、假设、理由和未满足条件；不合适就继续说，不必手写 JSON。

标准 MCP 协议与工具测试已通过；各厂商客户端／模型尚未逐一验收。每服务进程单用户，个人记忆留在本机。完整说明见 [MATCHING.md](MATCHING.md)。

### 方式二：Mac 本机网页工具测试台

双击 `start_simulator.command`，隐藏输入本人 Token，打开 **http://127.0.0.1:8789/**。也可在已安装依赖的环境运行 `python3 simulator.py --token-stdin`。

连接账号 → 填城市、关键词、目标时间 → 读取撮合上下文与菜单 → 准备候选商品 → 手动录入食品需求，或导入宿主模型生成的 intent → 撮合 A/B。可恢复会话、查看／清除记忆、反馈与重新核价；选中且明确授权才能创建，硬条件未解决时禁止创建。

**网页是业务工具测试台，不是独立自然语言助手。** 把整段口述粘进网页不会自动完成复杂语义理解；自然对话请使用方式一。Mac 听写只负责把语音转成文字。

### 方式三：无需账号的离线演示

下面旧版 `python3 decision.py serve --demo` 可演示人数变化、锁定和预算取舍，使用合成餐品／价格，不代表真实订单或节省金额。

## 可直接尝试的连续对话

以下是**使用示例**，不是预先核价的订单。当前价格必须查询官方数据。

> 我跟Maggie和Tom，三个人，今天下午三点在上海七宝地铁站附近取餐。我要鸡腿堡，Maggie一个汉堡加饮料，Tom想吃鸡翅，尽量省钱。给两个组合，说明每人吃什么、用了什么券、总共多少钱。

收到 A/B 后可以继续：

> Tom改成小食套餐，我不要可乐，换牛奶。其他条件保留。

再比较距离和价格：

> A走得有点远，优先找近一些的；总价尽量不超过一百。

选定后：

> 选B，按刚才展示的金额下单。

本机偏好记录例子：

> 长期记住我喜欢鸡腿堡。今天减脂，汉堡先按不加酱配；这是本次要求，不要永久记住。

模糊含义进一步修正例子：

> 我说不要调料，是不要汉堡酱，肉饼原有的盐可以。Maggie只是不要生菜，洋葱可以。

模型应更新语义并保留其余上下文。但官方特制去酱／去菜当前未接通，不能凭这段解释声称已完成改配或直接创建。

## 当前实测到了哪一步

- 69 项自动回归通过，覆盖标准 MCP、HTTP、多人容量、语义记录、连续修正、本机记忆、模拟创建与失败防重；Skill 格式和页面脚本验证通过。
- 真实账号、附近门店、菜单与官方整单核价已联调。历史一人汉堡＋可乐例子两店均 ¥14.90；六人条件场景曾返回两组 ¥169，**仅包含已映射五人食品**，不满足完整六人需求，不能下单。两者都是测试时点记录，不是当前价格。
- 浏览器真实只读 A/B 显示和硬条件下创建按钮禁用已验收。没有创建或支付真实订单；真实带券成功报价、预约创建和跨模型行为仍待验收。
- 暂不支持配送、多门店拆单、路线导航、特制去酱／去菜、积分兑换、自动付款；麦金卡状态／会员活动优惠归因未知时明确未知。

详细证据：[VALIDATION.md](VALIDATION.md)。不要把下面旧版演示、合成测试或“接口已实现”当作真实交易验证。

## 历史入口：团餐变更决策台（v2）

**新增 Mac 本机真实点餐模拟器**：独立网页界面，连接本人 Token，查看积分与卡包、搜索真实门店、读取默认套餐组成、准备核价候选、重算人员变更，并进行官方整单核价。当前接口未提供麦金卡持卡状态，显示无法确认。双击 `start_simulator.command`，或运行 `python3 simulator.py --token-stdin`。完整使用和实测边界见 [LIVE_WORKBENCH.md](LIVE_WORKBENCH.md)。离线演示仍可按下面方式无 Token 使用。

**有人变卦，不必整桌重来。**

10 人 workshop 配好餐之后，一人退出、一人改成不辣，或者优惠券失效：保留已认可的餐品，计算最少影响几个人、需要换哪些餐、现金如何变化。面向会议组织者、团餐发起人和需要比较调整代价的个人用户。

v2 新增确定性求解器、浏览器交互台、命令行和本地 MCP 工具。**离线决策链路不联网、不下单、不领券、不兑换。** 无 Token 即可体验。实时工作台补充主动查询和默认餐适配，仍须官方整单核价。

## 30 秒体验

Python 3.11+；新决策台只用标准库，不必安装旧界面的依赖。

```bash
git clone https://github.com/godlockin/BigMacMcpCN.git
cd BigMacMcpCN
python3 decision.py serve --demo
```

打开 **http://127.0.0.1:8788**，点击「演示：一人退出＋一人不辣」。页面显示旧方案、新方案、受影响人数、金额变化和预算取舍。可逐人勾选锁定、修改预算、模拟优惠券失效，下载决策 JSON。

> `examples/workshop.json` 是 10 人**合成数据**，餐品、价格、属性均非麦当劳实时数据。页面持续显示来源，不将演示结果冒充实际节省。

```bash
python3 decision.py plan --demo --output decision-result.json
python3 decision.py plan --input my-request.json
python3 decision.py serve --input my-request.json --port 8789
```

CLI 无可行方案返回 2，输入错误返回 1。有方案但搜索达到上限时为 `feasible`，不是已证明最优；应读取 JSON 状态。

## 差异化能力

| 问题 | v2 的处理 |
|---|---|
| 有人退出，别人已经选好了 | 移除退出者，优先保留其他人的餐；退出者不计入受影响人数 |
| 一个人临时改要求 | 基于每人的允许候选与已确认标签重新分配；未知属性不视为满足 |
| 已确认的餐不能改 | `locked_people` 锁定餐品组成；冲突时明确无解，不静默解锁 |
| 同一餐的券失效了 | 可转为相同餐品的无券候选；显示权益／价格变化，不误算为改餐 |
| 预算不足，究竟差多少 | 完整搜索后给出满足其他条件的最低预算与缺口 |
| 多花一点能少改几个人？ | 输出各个受影响人数对应的最低现金支出 |
| 券或积分被重复使用 | 共享资源容量与总积分余额约束参与搜索 |
| 搜索太大 | 明确返回截断状态，不将未找到说成无解 |

目标按字典序排列：**受影响人数 → 餐品增删件数 → 现金支出 → 积分消耗**。换一个商品记为一次移除和一次加入，共 2 件改动。预算、饮食、锁定和资源条件均先作为硬约束。

## 输入契约与边界

完整格式见 [examples/workshop.json](examples/workshop.json)。

- `snapshot`：来源 `synthetic` 或 `user_snapshot`、时间、门店、完整餐候选、资源容量、积分余额。
- 候选：唯一 `id`、名称、**整数分**价格、餐品类型列表 `items`、已确认属性 `verified_tags`、积分消耗和资源 ID。重复资源 ID 表示消耗多个单位。
- `participants`：稳定个人 ID、名字、允许候选、必需属性。每人只分配一个**完整餐候选**；套餐内部组成须提前核实。
- `previous_assignments`：上次结果的 `assignments` 原样传入，保留原价格和餐品组成。退出者从当前参与者移除。
- `locked_people`：必须同时存在于旧、新参与者中。保护餐品组成，不保证旧价格或旧券继续有效。
- `budget_cents`：总现金预算。营养、优惠有效期和可售时段须由快照准备方核实后筛选。

范围：1–16 人，最多 64 个候选，默认 200,000 个搜索节点（可配置至 500,000）。只在提供的候选与资源规则内计算；**不自动枚举官方全菜单、不拆分共享套餐、不推断券叠加、不证明全市场最低价**。整数分合计不是最终支付金额。

| 状态 | 含义 |
|---|---|
| `optimal` | 搜索完成，候选空间内按既定目标最优 |
| `feasible` | 有可行方案，但搜索被截断 |
| `infeasible` | 搜索完成或个人候选直接冲突，给定条件无解 |
| `unknown` | 搜索被截断且尚无预算内方案 |

只有搜索完成才提供 `minimum_budget_cents` / `minimum_extra_budget_cents`；截断时仅提供已找到的金额，并明确未证明。

## 原版本迁移

v1 自然语言 Deal 仍是启发式草案。v2 修复轮流选贵套餐、数量计数和积分重复统计；不再凭名称断言素食／不辣，或把同类商品优惠券直接套用。

旧解析器没有证据证明的券适用范围和积分兑换关系，默认不应用。`verified_*` 是内部确认标记，**不是官方响应字段的声明**。复杂个人约束使用新工具；旧报告“规则通过率”不是成功下单概率。

旧 `run.py` 的监控与消耗类操作不属于本次新决策链路，新演示不启动这些路径。未核验自动化调用授权，不建议把旧监控作为默认演示入口。

```text
decision.py                   # CLI / 本机 HTTP 服务
web/decision.html             # 浏览器变更工作台
mcd_assistant/decision.py     # 纯函数求解器
examples/workshop.json        # 合成场景
tests/                        # 行为、回归、穷举和接口测试
```

独立参赛作品，非麦当劳官方产品。保留官方原版 [参赛声明](CONTEST_DECLARATION.md)。v2 由 Codex 升级；[workbuddy.md](workbuddy.md) 仅记录 v1 作者提供的开发背景，不声称本次工作由 WorkBuddy 完成。
